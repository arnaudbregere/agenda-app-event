## 1. Issue #68 — suite e2e Playwright

PR [#70](https://github.com/arnaudbregere/agenda-app-event/pull/70), mergée et **déployée en prod** (`f43cf66`, vérifié via `/api/health`). Branche `feat/e2e-playwright`.

### Décisions de conception

- **Package `e2e/` indépendant** à la racine (pas dans `frontend/`) : orchestre à la fois le build frontend et le backend réel, ne dépend d'aucun des deux au runtime npm.
- **Mode de lancement** : `playwright.config.ts` fait builder le frontend (`npm run build --prefix ../frontend`, Vite) puis lance le **vrai** serveur Express backend (`npx tsx ../backend/server.ts`) qui sert ce build statiquement — exactement le setup de prod (`backend/src/app.ts`, bloc `FRONTEND_DIST`). Choix fait plutôt que `vite preview` (évite de réintroduire CORS/origine divergente de la prod).
- **Isolation des données** : nouvel override `EVENTS_DATA_FILE` dans `backend/src/utils/paths.ts` (défaut inchangé si absent) — la suite e2e écrit dans `e2e/.tmp/events.e2e.json`, jamais `backend/data/events.json`. `resetEvents()` vide ce fichier en `beforeEach` de chaque spec.
- **`workers: 1` / `fullyParallel: false`** : un seul backend réel et un seul fichier JSON partagés entre tous les tests, pas de parallélisation possible sans collision.
- **Sélecteurs** : rôles ARIA/labels accessibles (`getByRole`, `getByLabel`) en priorité, cohérent avec l'effort d'accessibilité du frontend. Les vues calendrier n'ayant pas encore de rôles dédiés, `views.spec.ts` retombe sur des classes BEM pour celles-ci.

### Couverture — 14 tests, 4 specs

| Fichier | Couvre |
|---|---|
| `crud.spec.ts` | Cycle CRUD événement (créer/éditer/supprimer + confirmation et annulation) |
| `views.spec.ts` | Les 4 vues (Mois/Semaine/Jour/Liste) |
| `mobile-sidebar.spec.ts` | Drawer sidebar à 320px (bouton, backdrop, Échap + restitution focus) |

## 2. Corrections post-merge — outillage TypeScript manquant dans `e2e/`

Deux allers-retours après le merge de la PR #70, signalés par l'utilisateur (éditeur puis terminal) :

| Symptôme | Cause | Correction |
|---|---|---|
| Éditeur : `Cannot find name 'process'` et `Property 'dirname' does not exist on type 'ImportMeta'` dans `playwright.config.ts` | `tsconfig.json` de `e2e/` référençait `"types": ["node", ...]` mais le paquet `@types/node` n'était pas dans les devDependencies | `@types/node` (`^20.19.43`, même version que `backend/`) ajouté |
| `npx tsc --noEmit -p tsconfig.json` dans `e2e/` échoue avec *"This is not the tsc command you are looking for"* (stub npx) | Aucun paquet `typescript` local dans `e2e/` — pas de script `typecheck` non plus à ce moment | `typescript` (`^7.0.2`) ajouté en devDependency, script `typecheck` créé, step correspondant ajouté au job CI `e2e` |

Leçon tirée pendant la session (vérification initiale défaillante) : un premier `npx tsc --noEmit` lancé avant le premier push avait semblé passer (`TypeScript: No errors found`), mais la sortie était en fait filtrée par le hook RTK installé sur la machine — la vraie commande locale n'avait jamais tourné correctement faute de paquet `typescript`. Confirmé en relançant avec `npx --package typescript -- tsc` après coup. D'où la nouvelle règle (section 3) : toujours un script `typecheck` dédié par package, jamais une invocation ad-hoc de `tsc` dont la sortie n'est pas garantie fiable.

Ces deux corrections sont parties dans la même PR #70 (avant son merge) puis dans des ajustements du job CI repris en section 4.

## 3. Durcissement du process

### `CLAUDE.md`, `.claude/rules/e2e.md` (nouveau), `.claude/agents/reviewer.md`

- **Règle ajoutée** : chaque package JS/TS du repo (`backend/`, `frontend/`, `e2e/`, tout futur package) doit avoir son propre `typescript`/`@types/node` en devDependencies, un script `typecheck`, et l'étape CI correspondante — motivée par l'oubli de la section 2.
- **Règle ajoutée** : avant tout `git push` (y compris un simple correctif sur une branche déjà poussée), présenter à l'utilisateur ce qui va être poussé et attendre son accord explicite — demandé explicitement par l'utilisateur suite aux deux allers-retours de la section 2.
- `.claude/rules/e2e.md` créé (miroir de `backend.md`/`frontend.md`) : conventions Playwright du projet (mode de lancement, isolation des données, `workers: 1`, sélecteurs ARIA, pourquoi le job CI est lent — voir section 4).
- `.claude/agents/reviewer.md` : lisait seulement `frontend.md`/`backend.md`, pas de vérification possible des conventions e2e sur un futur diff touchant `e2e/`. Ajouté à sa liste de lecture + nouvelle section de points à vérifier (webServer, isolation des données, `workers: 1`, typecheck du package).

## 4. PR #71 — lisibilité CI et vérification manuelle

PR [#71](https://github.com/arnaudbregere/agenda-app-event/pull/71), mergée et **déployée en prod** (`90b0454`, vérifié via `/api/health`). Branche `chore/ci-step-names`.

- **Déclencheur** : capture d'écran de l'utilisateur montrant 3 steps "Run npm ci" indistincts dans l'UI GitHub Actions (job `e2e`). Corrigé par un `name:` explicite sur chaque step (`Install backend deps` / `Install frontend deps` / `Install e2e deps`, etc.).
- **Question posée en retour** : pourquoi le job `e2e` prend ~8 min ? Vérifié via le détail des steps du run (`gh run view --json jobs`) :

  ```
  Install Playwright browser (npx playwright install --with-deps chromium)  →  8min 09s
  Run e2e tests                                                              →  15s
  ```

  Pas les tests (15s, identique au local) : le step `--with-deps` réinstalle Chromium + un lot de libs système via `apt-get` à chaque run, sans aucun cache. Documenté dans `.claude/rules/e2e.md`.
- Issue [#72](https://github.com/arnaudbregere/agenda-app-event/issues/72) ouverte pour traiter cette lenteur CI plus tard (cache `~/.cache/ms-playwright` ou image Docker `mcr.microsoft.com/playwright` préinstallée) — non traitée dans cette session, pas bloquante.
- Demande utilisateur satisfaite en parallèle : run local en mode headed (`npx playwright test --headed --reporter=line,html`, navigateur visible pendant l'exécution, 14/14 passés) puis rapport HTML Playwright généré et servi (`npx playwright show-report`, `http://localhost:9323`).
