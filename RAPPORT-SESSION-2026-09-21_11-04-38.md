## 1. Contraste WCAG AA — `--color-text-subtle`

Les 3 échecs de contraste relevés par l'audit du 15/09 (labels d'heure de la grille horaire, en-têtes du mini-calendrier, liste agenda) partageaient tous le même token CSS.

| Avant | Après |
|---|---|
| `#80868b` — 3.68:1 sur blanc / 3.46:1 sur `cloud-subtle` (sous le seuil AA 4.5:1) | `#6a6f73` — 5.08:1 sur blanc / 4.78:1 sur `cloud-subtle` |

- `frontend/src/styles/settings/_colors.scss` : token unique modifié, corrige d'un coup les 3 usages flagués par l'audit et 2 usages supplémentaires non flagués (icône recherche, pastille de catégorie par défaut).
- `DESIGN.md` et le sidecar `.impeccable/design.json` resynchronisés avec la nouvelle couleur.

## 2. Vérification visuelle en navigateur réel (non traitée le 15/09)

Vérification manuelle via l'extension Chrome (`claude-in-chrome`), point resté en suspens la session précédente faute d'extension connectée.

**Confirmé OK** : doublon d'icône "effacer" de la recherche toujours absent, cellules calendrier bien de vrais `<button>` avec labels ARIA, header responsive passant bien sur plusieurs lignes sous 600px (vérifié via injection CSS temporaire, l'outil `resize_window` de l'extension s'étant révélé peu fiable dans cet environnement).

**Bug trouvé et corrigé** :

| Symptôme | Cause | Correction |
|---|---|---|
| Échap ne fermait pas la modale événement (`EventModal.vue`), le piège Tab documenté en PR #13 ne s'activait jamais | Le focus n'entrait jamais dans la modale à l'ouverture : l'attribut HTML `autofocus` est peu fiable sur un élément inséré via `Teleport`+`Transition`. Le listener `@keydown` étant posé sur le `<form>` lui-même, il ne recevait l'événement clavier que si le focus était déjà à l'intérieur — jamais le cas en pratique | Focus explicite du champ `#event-title` via `nextTick()` à l'ouverture de la modale, au lieu de compter sur `autofocus` |

- Revérifié en direct après le fix : le focus entre bien dans `#event-title`, Échap ferme la modale et restitue le focus au bouton déclencheur, le piège Tab boucle correctement entre premier et dernier champ.
- Incident annexe : un événement de test créé par l'utilisateur pendant la vérification manuelle (`Test`, 09/09/2026) a été supprimé via l'API avant merge, pour ne pas polluer les données.
- `npm test` (frontend) : 42/42 verts après le fix.
- PR #15 (contraste + focus trap) : https://github.com/arnaudbregere/agenda-app-event/pull/15 — CI verte (backend + frontend), mergée en squash en `4000e81`. Déploiement vérifié (`/api/health` → `4000e81`).

## 3. Vérification de la persistance de `events.json`

Point de vigilance du 15/09 (disque non persistant sur Render free). Vérification ponctuelle demandée par l'utilisateur (pas de script ni de tâche planifiée mise en place) :

- Comparaison directe : `https://agenda-app-event.onrender.com/api/events` renvoie exactement l'événement commité dans `backend/data/events.json` sur `main` ("Formation Formapédia") — aucune perte de données détectée.
- Point notable partagé avec l'utilisateur : `backend/data/events.json` est **suivi par git** (pas dans `.gitignore`). Conséquence pratique : tout événement créé directement en prod, s'il n'est pas aussi commité, disparaîtra au prochain redémarrage/redéploiement du disque non persistant. Aujourd'hui prod == git, donc rien n'a été perdu depuis le dernier commit.
- Aucune modification de code pour cette tâche.
