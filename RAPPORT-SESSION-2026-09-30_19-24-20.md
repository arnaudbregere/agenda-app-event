## 2. Issue #40 — mobile-first, sidebar et recherche accessibles sous 900px

PR [#66](https://github.com/arnaudbregere/agenda-app-event/pull/66), mergée et **déployée en prod** (`662774a`, vérifié via `/api/health`). Branche `feat/mobile-first-sidebar-40`, 11 commits.

### Implémenté

- Store (`calendar.ts`) : `isSidebarOpen` + `openSidebar`/`closeSidebar`/`toggleSidebar`. `goToCurrent` (accès rapide sidebar) referme le drawer automatiquement.
- Sidebar en drawer superposé (`position: fixed`) sous 900px : fond cliquable, focus déplacé vers le premier élément à l'ouverture puis restitué au déclencheur à la fermeture, Échap referme.
- Bouton hamburger dans le header (`aria-expanded`/`aria-controls`, zone de tap 44×44 en `pointer: coarse`).
- Recherche repliée sous un bouton dédié sous 900px (toujours visible à partir de 900px, comme avant).
- Migration mobile-first complète : `respond-down()` supprimé (plus aucun usage dans le projet), `respond-up()` généralisé à `_layout.scss`, `_app-header.scss`, `_view-switcher.scss`, `_calendar-month.scss`, `_utilities.scss`.

### Bugs trouvés et corrigés en testant à 320px (navigateur réel, via iframe — `resize_window` indisponible dans cet environnement, fenêtre fixe)

| Symptôme | Cause | Correction |
|---|---|---|
| Débordement horizontal à 320px | `.o-app-shell__header` (item de grille) sans `min-width: 0` — la colonne `1fr` s'élargit au min-content du header (titre en `white-space: nowrap`) | `min-width: 0` ajouté sur `__header`, même piège déjà connu sur `__main` |
| Débordement horizontal (2e cause) | `.c-app-header__nav` avait `flex-shrink: 0` hérité de l'ancien CSS desktop-first, poussait hors du viewport | `nav`/`__title` passent en `flex: 1 1 auto` + `min-width: 0`, titre tronque en ellipsis ; desktop inchangé (`flex: 0 0 auto` dès 900px) |
| Recherche mobile ne s'affichait jamais | Sélecteur Sass invalide : `&.is-search-open { &__search {...} }` — dans ce bloc `&` vaut déjà `.c-app-header.is-search-open`, donc `&__search` produisait `.c-app-header.is-search-open__search` (jamais matché) | Sélecteur réécrit à plat (`&.is-search-open &__search`, descendant réel) |
| Focus perdu après Échap en recherche mobile | `<input type="search">` retire nativement le focus après nos gestionnaires, même avec `preventDefault()` | `setTimeout(0)` repousse le `focus()` de restitution après ce retrait natif |

Cycle complet (création → édition → suppression d'événement) et les 4 vues vérifiés sans débordement à 320px. Layout desktop (1280px) revérifié inchangé.

**Point non corrigé, signalé mais pas un bug introduit par cette session** : pile à 900px (juste au-dessus du seuil `md`), le champ de recherche s'écrase temporairement (placeholder tronqué "Re..."). Vérifié : le calcul flex de l'ancien CSS desktop-first aurait produit exactement le même résultat à cette largeur précise — préexistant, pas une régression. Disparaît dès ~1024px. Laissé tel quel, décision de l'utilisateur de ne pas complexifier davantage — pas de suivi ouvert dessus.

### Retours de relecture utilisateur, traités avant merge

- **Commentaires trop nombreux / référençaient "issue #40" dans le code** : passage de nettoyage (commit `288fa40`) — gardé uniquement le WHY non-évident (pièges `min-width: auto` implicite grid/flexbox, nesting Sass `&`, quirk navigateur sur `<input type="search">`), retiré toute référence à l'issue (doit vivre dans la PR, pas le code).
- **`AppHeader.vue` « touffu »** : simplifié (commit `76b4510`) — une ref en moins (focus direct sur l'`<input>` plutôt que `querySelector`), `closeMobileSearch` fusionné dans son seul appelant, fonctions regroupées par sujet (résultats / repli mobile / sidebar) avec un commentaire par groupe au lieu de dispersés.
- **Divs non sémantiques dans `App.vue`** : `AppHeader`/`AppSidebar` ont déjà `<header>`/`<aside>` en racine — les `<div class="o-app-shell__header">` / `__sidebar` qui les enveloppaient ne servaient qu'à poser une classe CSS, que Vue transmet automatiquement à la racine d'un composant single-root. Supprimées. Backdrop marqué `aria-hidden="true"` (décoratif, Échap couvre déjà le clavier).

Chaque étape revérifiée en navigateur (sidebar, recherche mobile, focus, Échap) à 320px et desktop après simplification — aucune régression, 117/117 tests, typecheck et build propres à chaque commit.
