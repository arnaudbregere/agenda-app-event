## 1. Migration CSS → SCSS (`206c390`)

- Tous les fichiers `_*.css` de l'architecture ITCSS (`settings`, `tools`, `generic`, `elements`, `objects`, `components`, `utilities`) renommés en `.scss`.
- Ajout de `tools/_mixins.scss` avec le mixin `respond-down()`, pour factoriser les media queries `max-width` par breakpoint (seul point où le CSS natif ne suffisait pas — les design tokens restent en custom properties CSS pour la thémabilité à l'exécution).
- Composition via `@use` (modules Sass) plutôt que `@import`.
- Dépendance `sass` ajoutée, `main.scss` importé depuis `main.js`.
- README mis à jour pour refléter le passage à SCSS.

---

## 2. Commit Git exposé sur `/api/health` (`76915b6`)

`backend/server.js` renvoie désormais `{ status: "ok", commit }` :
- utilise `RENDER_GIT_COMMIT`, définie automatiquement par Render à chaque déploiement ;
- fallback sur `git rev-parse HEAD` en local (où cette variable n'existe pas) ;
- résolu une seule fois au démarrage, pas à chaque requête.

Permet de vérifier en un `curl` quelle version tourne (local ou prod), sans passer par le dashboard Render.

## 3. Suite de tests + CI (non commitée)

### Tests

**Vitest** ajouté sur les deux packages (`npm test` = run, `npm test:watch` = watch mode) :

| Fichier | Cible |
|---|---|

| `frontend/src/stores/events.test.js` | Store Pinia — actions CRUD |

**76 tests au total** — 34 backend, 42 frontend — tous passants.

### Fix associé

`backend/src/utils/validators.js` : les vérifications de longueur/vide du champ `title` sont passées dans un `else if` (au lieu de blocs `if` indépendants), pour éviter un crash si `title` n'est pas une chaîne de caractères — découvert en écrivant les tests de validation.

### CI GitHub Actions

`.github/workflows/tests.yml` ajouté : deux jobs (`backend`, `frontend`), déclenchés sur push/PR vers `main`, chacun fait `npm ci` puis `npm test` dans son répertoire respectif, avec cache npm par `package-lock.json`.
