## 3. Épinglage `typescript` — vérification et levée partielle

- Vérification complète dev→prod demandée par l'utilisateur : `typecheck`/`build`/`test` des deux côtés, démarrage local comme Render, `/api/health` prod — tout cohérent sur `da6fdca`.
- Re-testé si `vue-tsc` supporte désormais TypeScript 7 (demande explicite « être serein du dev à la prod ») : dans un dossier isolé (`/tmp`, hors dépôt), `vue-tsc@3.3.11` (dernière version publiée) contre `typescript@7.0.2` (dernière stable) échoue toujours avec `ERR_PACKAGE_PATH_NOT_EXPORTED`, identique à l'incident de septembre. Blocage confirmé toujours réel côté frontend.
- Découverte en creusant : le backend n'a **jamais** eu besoin de cet épinglage — il n'utilise que `tsc` en direct, jamais `vue-tsc`. Testé dans une copie isolée du backend avec `typescript@7.0.2` : `typecheck --strict`, `build`, 34 tests identiques. PR [#52](https://github.com/arnaudbregere/agenda-app-event/pull/52), mergée en `1ea8c9a` : `backend/package.json` passe à `typescript: ^7.0.2`. Frontend resté sur `^6.0.3`, `README.md` mis à jour pour préciser que l'épinglage est frontend-only, avec la date de vérification.
- Vérification supplémentaire : pas de Dependabot/Renovate configuré sur ce dépôt, donc aucun risque de bump automatique silencieux — un changement de version ne peut venir que d'une PR humaine, passée par la CI.

## 4. Corrections de sécurité et nettoyage npm

Suite d'un audit complet demandé par l'utilisateur (« plus de problèmes de vulnérabilités, de dépréciation ou de faille de sécurité ? »). PR [#53](https://github.com/arnaudbregere/agenda-app-event/pull/53), mergée en `59ee985`.

- **`qs`** : `6.15.3` → `6.16.0` via `express`/`body-parser` mis à jour dans leur range déjà accepté (`^4.19.2`), `npm audit fix`, aucun changement de `package.json`. Corrige 2 failles modérées (bypass `array-limit`, DoS `isBuffer`).
- **`uuid`** : `9.0.1` → `14.0.2`. Classé « breaking » par npm à cause du saut de version majeure, vérifié sans risque avant application : seul usage dans le code (`v4 as uuidv4`, `eventsController.ts`), export toujours présent en v14. Testé dans une copie isolée (`typecheck --strict`, `build`, 34 tests, puis un vrai `POST` sur le serveur démarré depuis `dist/` — id généré conforme au format UUID v4) avant d'appliquer au dépôt réel.
- **`@types/uuid`** : retiré — stub déprécié depuis que `uuid` fournit ses propres types (confirmé via `npm view @types/uuid deprecated`), ajouté par erreur à l'étape 6.1 sans vérification. `typecheck --strict`/`build`/34 tests inchangés sans lui.
- `npm audit` : 0 vulnérabilité après (contre 4 modérées avant). Revérifié sur le dépôt réel avec un cycle CRUD complet après application, `backend/data/events.json` sauvegardé puis restauré, aucune diff.
- Vérifié en complément : frontend déjà à 0 vulnérabilité, aucune dépréciation à l'installation ni backend ni frontend après ces corrections. `npm outdated` liste quelques montées de version mineures disponibles (`express` 5.x, `vite`, `vue`, etc.) — non traitées, hors périmètre d'une correction de sécurité, aucune n'est signalée par `npm audit`.
